# 交替打腿外骨骼运动感知与髋关节辅助仿真：第一阶段

本项目为可运行的研究原型，人体身高参数 1.75 m、质量 70 kg。固定骨盆及外骨骼腰部支撑、水平俯卧、仅矢状面屈伸、踝关节固定。重力保留，不计算水动力、浮力、接触碰撞或推进速度。地面仅用于显示。

项目分为两部分，均为增量关系：

- **无助力基础实验**：`simulate.py`、`validate.py`、`config.json`，输出至 `output/` 与 `validation/`。
- **髋关节辅助力矩实验**：`assistance_*.py` 系列，复用第一部分的 `build()`、`target()` 和绘图函数，在保留原计算顺序的基础上增加助力控制与记录；输出至 `assistance_output/`，不覆盖第一部分的任何文件。

## 运行

在 PowerShell 中：

```powershell
Set-Location E:\reasearching\flutter_kick_sim
# 无助力基础实验
.\.venv\Scripts\python.exe simulate.py
.\.venv\Scripts\python.exe simulate.py --viewer
.\.venv\Scripts\python.exe validate.py
# 髋关节辅助实验（四组各运行24秒；仅写 assistance_output）
.\.venv\Scripts\python.exe assistance_sim.py
# 单独查看 G2，输出目录仍按组分开
.\.venv\Scripts\python.exe assistance_sim.py --mode G2 --viewer
# 所有独立验证，包括旧脚本原逻辑和四组步长减半
.\.venv\Scripts\python.exe validate_assistance.py
```

`simulate.py` 第一条生成 24 秒数据和图表；第二条打开交互模型窗口并实时运行；`validate.py` 执行独立几何、传感器轴向、采样同步、零力矩和物理步长减半验证。提前关闭窗口时至少运行 7 秒才能生成稳态统计。若需新建环境：`python -m venv .venv`，随后使用该环境的 pip 安装 `requirements.txt`。

其他示例：

```powershell
.\.venv\Scripts\python.exe simulate.py --duration 60 --out output_60s
.\.venv\Scripts\python.exe simulate.py --ideal --out output_no_noise
.\.venv\Scripts\python.exe simulate.py --dt 0.0005 --out output_half_dt
# 自定义辅助实验另存，避免覆盖本次助力结果
.\.venv\Scripts\python.exe assistance_sim.py --out assistance_output_trial2 --assistance-config assistance_config.json
```

`--ideal` 仅关闭人为传感器噪声及固定陀螺零偏，动态加速度引入的倾角误差仍然存在。修改 `config.json` 可调整人体、绑缚、控制和传感器参数。生成的 model.xml 用于模型检查；实际 PD 控制与柔性绑缚力在 Python 中实现，单独打开 XML 不会复现完整试验。

辅助实验中：`--config` 读取人体/模型/噪声配置；`--assistance-config` 读取助力配置。修改人体参数时，建议复制原 config 为新文件，再让全部组共享该文件，不修改原基准。`--dt`、`--duration`、`--ideal` 可用于额外实验；`--ideal` 仅关掉噪声/固定陀螺零偏，不关掉动态加速度。验证脚本针对根目录当前默认配置和默认四组结果运行，修改配置后先重跑全部组。不要用 `--ideal` 结果冒充默认有噪声对比。提前关闭 viewer 得到的是缩短实验，不应与完整24秒实验直接比较；不足稳态统计时长会报错。

## 模型与坐标

- 世界 X 轴由髋指向初始伸直的腿部，Z 轴竖直向上，Y 轴沿髋膝屈伸轴。左右腿在 Y 方向分开。
- 人体髋角为绕 +Y 的转角，膝屈曲为绕 -Y 的转角；两侧使用相同解剖角度正方向。
- 人体与外骨骼分别具有四个关节，共 8 个自由度。初始轴线重合；轴线上侧方电机与人体关节中心的 Y 坐标不同，不影响初始同轴。
- 外骨骼髋轴固定在腰部支撑上；膝轴随外骨骼大腿杆运动，因此可以与人体膝中心出现小幅偏移。平面模型不模拟轴线倾斜。
- 绑缚位于大腿、小腿各自长度的 70%。外骨骼侧用虚拟袖套连接点跨越侧向距离，使两条运动链在初始姿态的连接点重合。
- 每对连接点施加等大反向的 `F = k*(p_exo-p_human) + c*(v_exo-v_human)`；通过点雅可比转为广义力，包含力臂作用。该模型表示局部线性柔性连接，不表示真实绑带的张力单向性、松弛、皮肤滑移或接触压力。
- 金属杆件为刚体；关节采用可转动铰链。DM-J6006-2EC 以质量、被动阻尼/摩擦、等效转子惯量及零力矩执行器近似，不是厂家完整机电模型。
- 四个人体执行器采用带重力/科氏偏置补偿的 PD 力矩控制和 150 Nm 限幅；这不是肌肉或 EMG 模型。
- 外骨骼执行器：无助力实验中四个外骨骼执行器始终为零主动输出；辅助实验中仅左右髋电机（`exo_L_hip_motor`、`exo_R_hip_motor`）可施加助力力矩，左右膝电机始终为零。

## 人体尺寸、质量和脚蹼

大腿长度为 `0.245*height`（0.42875 m），小腿为 `0.246*height`（0.43050 m）。每侧大腿、小腿、足部分别使用人体质量的 10%、4.65%、1.45%；其余 67.8% 集中于固定骨盆/躯干。人体总质量恰为 70 kg；每只脚蹼另加 0.5 kg，不计入人体质量。固定骨盆上的质量不参与自由运动。

这些比例是本原型的工程近似，未按该用户实测肢段辨识。几何惯量由简化胶囊体/长方体计算。175 cm 是人体参数化尺度，不是包含脚蹼后的外形总长。足与小腿初始沿同一方向固定，属于流线型姿态假设，未映射为临床定义的具体踝角。

外骨骼杆件质量（0.35/0.25 kg）、电机质量（0.335 kg）、阻尼、摩擦、armature、绑缚刚度（2500 N/m）和阻尼（45 Ns/m）均为待实测核对的参数。没有把电机额定扭矩用于限制人体驱动力矩。

## 轨迹和论文使用边界

参考 Yang 等，2026，DOI: https://doi.org/10.1016/j.jbiomech.2026.113285 的正常速度条件，设置 0.67 Hz 周期，以髋/膝关键角度与时刻构造周期三次样条。左右相差半周期是本项目假设。

这不是论文原始数据或图像数字化复现。中间控制点为人工近似，样条可能出现峰值过冲；PD 跟踪也存在误差。因此输出 ROM 和峰值不必等于论文表 2，不能据此声称准确复现论文。后续获得数字化或原始周期数据后，应替换 HIP/KNEE 曲线，并校核角度零点、ROM、角速度峰值及相位。固定踝关节后不研究髋—膝—踝完整协调，也不重现肌肉协同。

0–2 s 为静止准备，1–1.8 s 用于陀螺零偏估计，2–4 s 平滑增加运动幅度；6 s 后计算稳态指标。辅助模式默认 4 s 开启、1 s 平滑增幅。

## 五 IMU 与编码器

五个 IMU 位于人体骨盆、左/右大腿、左/右小腿。大腿和小腿 IMU 放在肢段前侧附近，位置相对于旋转中心的偏置参与加速度计算。假设传感器与人体刚体牢固连接，不包含皮肤软组织伪影。

默认 1000 Hz 物理积分、100 Hz 输出。每次采样在同一时刻重新计算状态、控制、绑缚力和传感器，避免位置与加速度相差一个物理步。时间戳取整数步数生成。CSV 是浮点 SI 单位，非 CAN 报文。

原始加速度是 IMU 局部坐标系的比力，陀螺是局部角速度。对于固定在 world 上的骨盆，当前 MuJoCo 构型返回零静态加速度，因此显式使用 `-R_site^T * gravity` 构造受支撑的静态比力，其余四个 IMU 使用引擎 accelerometer。静止时各传感器比力模长应约为 9.81 m/s²。

安装角使用已知的绕 Y 固定旋转（0、7、-5、-6、4 度）进行 sensor-to-segment 变换；不是从单次静止姿态估计未知三维安装矩阵。静止阶段估计初始倾角及陀螺零偏。运动阶段使用平面互补滤波：陀螺梯形积分预测，加速度倾角作低增益修正，并按加速度模长偏离重力的程度降权。动态加速度即便模长接近重力也会造成误差，当前滤波器不消除此问题。

人体肢段绕 Y 的姿态角 theta 等价于旋转矩阵 Ry(theta)。髋角为 `theta_thigh - theta_pelvis`，膝角为 `theta_thigh - theta_shank`；这是严格平面条件下相对旋转的标量形式，不是通用三维欧拉角相减法。角速度由变换到统一轴后的相邻陀螺差分取得。无磁力计，不估计三维航向。

HWT905-CAN 在本阶段仅为后续硬件目标。噪声和固定零偏为可复现的假设值，尚未依据实测标定；未实现 CAN 编解码、量化、时延、丢包、内部带宽和硬件饱和。不能把本结果解释为 HWT905 的实测精度或厂家内部算法。

编码器当前为外骨骼关节的理想位置/速度读数，没有额外量化和噪声。姿态滤波器不使用编码器或人体关节真值反馈；真值只用于控制、记录和评价。人体运动与编码器运动的差异不归为 IMU 误差。

## 共同物理条件与人体控制

辅助实验沿用 175 cm、70 kg、8 自由度的独立人体—外骨骼运动链、固定骨盆与外骨骼腰部支撑、固定踝角、两侧大腿/小腿柔性绑缚、5 个 IMU 和 100 Hz 采样。保留重力，不新增水动力、浮力、接触、绳索或肌肉模型。

四组均使用同一个人体参考函数、PD 增益、力矩能力上限、初始 qpos/qvel 和随机种子。人体力矩为：

`tau_h = clip(tau_P + tau_D + tau_dynamics + tau_feedforward, ±human_limit)`

其中 `tau_P=Kp*(q_ref-q)`、`tau_D=Kd*(v_ref-v)`，`tau_dynamics=scale*qfrc_bias`。`qfrc_bias` 包含重力和科氏/离心项，不能称为纯重力补偿。默认 `scale=1`、新增前馈为全零，保留旧版控制。分别记录 P、D、反馈和、前馈、动力学补偿、限幅前总力矩、实际力矩及限幅修正。

人体控制器没有实验组别参数，不能按 G1/G2/Oracle 人为减小力矩。它仍使用人体状态真值作为模拟内部本体反馈，和旧版本一致；这不意味着外骨骼控制器可以获得这些真值。`adaptation="none"` 是后续主动适应模型的显式接口，本阶段其他值会被拒绝。人体增益/能力在共享基础配置中，前馈与补偿比例在助力配置 human 中；不得按组修改。

## 执行器和工程参数

新增力矩只赋给 `exo_L_hip_motor`、`exo_R_hip_motor`，左右外骨骼膝电机始终为零。施加顺序为：髋关节力矩作用于外骨骼链，外骨骼改变绑缚连接点位姿/速度，弹簧—阻尼力再作用于两条链。人体力矩表达式不加入外骨骼辅助项；`qfrc_applied` 只存绑缚力。

默认辅助幅值 2 Nm、执行器限幅 3 Nm、变化率限制 20 Nm/s、一阶时间常数 0.03 s。**这些全部是可配置的工程占位值，不是已核实的 DM-J6006-2EC 规格，也不构成实物控制参数建议。** 原模型中的被动摩擦、阻尼、armature、杆件质量等仍是原有假设，待实测辨识。

每个物理步：目标力矩限幅 → 可选一阶响应 `gain=1-exp(-dt/tau)` → 实际输出增量硬限幅。`response_time_s=0` 关闭一阶响应，但保留幅值和变化率限制；不允许负时间常数或非正限幅。记录实际力矩，而非仅记录目标力矩。当前 3 Nm 幅值限制高于 2 Nm 辅助幅值，所以默认幅值饱和率为零；验证包含超限、反向阶跃的专门压力测试。

## 四种辅助模式与数据边界

四组模式共用同一个人体 PD 控制器、同一个参考轨迹、同一套初始状态和随机种子，**唯一区别是外骨骼助力力矩的相位来源不同**，这样对比结果才有意义。

| 模式 | 在线输入 | 生成方式 | 本质 |
| --- | --- | --- | --- |
| G0 | 无需运动信号 | 两髋目标力矩为零 | 无助力基线 |
| G1 | 时间戳、预设频率/相位 | `A*sin(2*pi*f*(t-epoch)+side_phase+offset)` | 开环预设振荡器 |
| G2 | 当前/历史 IMU 解算的两侧髋角、相对陀螺角速度、时间戳 | 在线相位平面估计后 `A*sin(phase+offset)` | 基于 IMU 的闭环相位估计 |
| Oracle | 仿真实际人体髋角/角速度定义的相位真值 | 与 G2 同一波形，仅替换相位来源 | 理想相位（仅诊断用） |

四者的层级关系（逐步消除误差来源）：

```
G0 (零助力)
  ↓ 施加助力，但用预设时钟相位
G1 (开环预设振荡器)
  ↓ 把时钟相位换成 IMU 在线估计的相位
G2 (基于 IMU 的闭环相位估计)
  ↓ 把 IMU 估计相位换成仿真真值相位
Oracle (理想相位诊断)
```

各模式说明：

- **G0**：左右髋辅助力矩始终为零，作为对照组，量化施加辅助力矩后人体负担的变化。
- **G1**：完全不看传感器，只用系统时钟按预设频率和相位生成正弦力矩。左右腿预设相位差 π。优点是不受传感器噪声影响；局限是假设运动严格按预设频率和相位进行，一旦人体运动与预设不符，助力就会错位。
- **G2**：实时从 IMU 解算的髋角/角速度估计运动相位，再用该相位生成正弦辅助力矩。两侧腿独立估计，不强制相差 π（暴露估计误差而非掩盖）。估计有有效性判定：历史窗口内髋角峰峰值 ≥ 10° 且样本数 ≥ 30，否则输出零力矩。
- **Oracle**：用仿真器内部的人体真实髋角/角速度计算相位，跳过 IMU 估计环节。波形生成方式与 G2 完全相同，唯一区别是相位来源是真值。它与 G2 的差距 = 仅由相位感知误差造成的性能损失。

关于 Oracle 的重要说明：Oracle **不是最优辅助策略，也不是收益上界**，只消除了"相位感知误差"这一个因素。辅助幅值（2 Nm）未必最优，正弦波形未必是最优助力曲线，人体姿态和动力学补偿会随助力发生变化。因此判断助力效果不能只看总力矩大小，要同时看力矩分量（P/D/补偿/前馈）、跟踪误差和机械功。

所有辅助模式默认 4 秒开启、1 秒平滑增幅。G1 左右预设差 pi；G2 两侧分别估计，不用强制相差 pi 来掩盖估计误差。G2 历史窗口 1.5 秒，至少 30 个样本、角度范围至少 10° 才输出；不运动或历史不足时请求为零。时间戳只用于缓启动、历史窗口和顺序检查，不用于 G2 的周期相位推进。

G1 的预设频率/起始相位是公开工程设置，即使默认数值恰好与实验参考频率一致，也不在线访问 `target()`、参考轨迹或仿真状态。G2 固定相位中心 25°、速度归一化频率 0.67 Hz 也是显式先验，并非从在线真值或未来轨迹获取；它尚不是自适应频率振荡器。变化频率/幅度、误差安装和停止识别是后续鲁棒性试验范围。

## 相位定义与采样时序

实际非正弦运动没有唯一的"真实相位"。本阶段采用可复现的**状态相位**：

`phi(q,v) = atan2(v/(2*pi*f_scale), center-q) mod (2*pi)`

最低角附近为 0，屈曲过程中 sin(phi)>0，最高角附近为 pi，伸展过程中 sin(phi)<0。其角速度不必恒定，不等同于参考曲线的均匀时钟相位。

- `phase_true_rad`：实际人体 q/v 计算的状态相位，只供 Oracle 和离线评价。
- `phase_imu_rad`：相同定义应用于在线 IMU 估计；所有组都运行相同传感器链，以便比较。
- `phase_reference_rad`：参考生成器时钟相位，仅诊断记录，不能输入 G1/G2。
- `phase_valid`：传感器历史运动范围/样本数判定；静止阶段相位数值不具有有效周期意义。

控制请求在 100 Hz 采样完成后更新，从**下一物理步**开始经过执行器响应，其间零阶保持。这避免当前加速度同时决定当前力矩的代数环。CSV 中 `request_held_Nm` 是当前物理步使用的请求，`request_next_Nm` 是本次采样刚生成的请求；不能将两者混为同一时间的实际力矩。默认 1 ms 物理步；步长减半时这个一物理步延迟也减半，收敛检查包含该差异。

## 记录和指标定义

辅助实验 `sensors_100hz.csv` 保留旧版所有测量列，新增相位、人体力矩分量、绑缚三轴力与相对位移、功率、限幅状态、力矩变化率等。加速度仍是比力；固定骨盆处理、安装变换、噪声、标定和互补滤波与旧版一致。编码器仍是理想外骨骼关节位置/速度，不是人体真值。

`physics.csv` 记录每个积分区间左端的力矩、功率、关节状态、绑缚力/位移及限幅信息；没有把低频数据插值成高频测量。所有功与 RMS 代理指标在物理频率计算，统计窗口默认 `[6,24)` 秒，100 Hz 图表包括 24 秒端点。

- 每关节人体主动 RMS 力矩：实际净关节驱动力矩的时间 RMS，**包含动力学补偿**。
- 四关节合计 RMS：`sqrt(mean(sum_j(tau_h,j^2)))`，不是四个关节 RMS 的算术平均。
- 人体正机械功：`sum_j integral max(tau_h,j * qdot_h,j,0) dt`。先每关节取正再求和，避免正负关节功相互抵消。
- 外骨骼输出功：使用实际执行器力矩乘外骨骼关节速度，分别给出正功、负功和净功；不是人体侧收到的净能量，也不是电能或电机效率。
- 人体力矩分量 RMS 用于检查补偿变化；各分量 RMS 不能直接相加得到总 RMS。
- 跟踪误差相对共同人体目标；人机差异相对外骨骼编码器；IMU 误差相对人体实际真值，三者分开。
- 电机幅值饱和率：请求超出允许幅值的物理步比例；变化率受限率为一阶响应后的目标增量触及变化率限制的比例。另给实际力矩最大变化率。比例用稳态窗口，最大变化率用全程。
- 绑带力/位移最大值统计全程，因此启动瞬态可能主导四组的相同最大值；完整时序保留供进一步分析。
- 求解器警告保存 MuJoCo 各 warning 计数；零警告不等于模型已被实物验证。

## 独立验证及解释边界

无助力实验 `validate.py`：独立几何、传感器轴向、采样同步、零力矩和物理步长减半验证。

辅助实验 `validate_assistance.py`：

1. 正负 1 Nm 髋脉冲：检查初始加速度与短时位移方向；检查直接人体 actuator 广义力为零，并验证柔性绑缚随后使人体运动。
2. G0 全列与原 `simulate.run()` 的同配置、同随机种子重放一致；旧输出不覆盖。
3. 执行原 `validate.py` 的 `main()`，只将其输出根目录临时定位到新目录，不修改原脚本。
4. 比较四组模型、人体参数、参考和初始状态哈希及逐采样目标数组。
5. G1 请求严格反相；G2/Oracle 检查两侧相位偏离 pi 及请求负相关（不要求非正弦状态相位严格相差 pi）。工程验收阈值：相位 RMSE<45°、请求相关系数<-0.8，不作为生理学标准。
6. G2 仅以已存 IMU 估计逐样本重放，复现请求；改变未来后缀不能改变过去输出，改变传感器输入必须改变后续输出。另检查模块导入边界，G1 不受传感器扰动影响。
7. 四组完整 24 秒、同噪声种子步长减半：关节角差异 RMSE<0.25°，人体合计 RMS 和正功变化<2%。阈值是本项目数值检查标准。
8. 验证前后原脚本、配置、README 和原 output/validation 全部文件哈希不变。

当前默认实验没有优化相位/幅值，也没有强制 G2 优于 G1 或 Oracle。Oracle 只是消除本定义下的感知相位误差，**不是最优辅助策略或收益上界**。因为人体姿态与动态补偿会随辅助发生变化，不能只依据一个总力矩值判断助力效果；应同时查看力矩分量、跟踪误差和机械功。

这里的"人体负担"只是理想净关节执行器代理指标，缺少肌肉共收缩、疲劳、主动适应和生理代谢模型。**不能解释为水下推进效率、耗氧量或代谢能耗改善，也不能据此批准实物助力参数。** 当前无浮力而保留重力，水平姿态的支撑补偿很大，会明显影响力矩和正功代理指标。
